# Compile-time constants

This example shows top-level constants generated by `#[copper_runtime]` and constants
merged from a normal Copper RON include.

- `MAX_DETECTIONS` is a primitive `usize`.
- `CAMERA_TRANSLATION` omits both `storage` and `unit`, so it is `f32` meters.
- `CAMERA_OFFSET` supplies millimeters, which are normalized to the same f32 meter storage.
- `CONTROL_PERIOD` selects `f64` while keeping the default coherent SI unit (seconds).
- `YAW_LIMIT` selects both `f64` and degrees; the generated value stores radians.

Constants use the same root-first include precedence as tasks and resources: when the root
file and an include declare the same `id`, the root declaration wins. Constants are baked
into the binary. If a runtime robot configuration changes a compiled constant, Copper emits
a warning and keeps the baked value.

`main.rs` also builds const `WorldFrame -> RobotFrame` and `RobotFrame -> CameraFrame`
`TypedTransform3D`s directly from the generated translation/rotation quantities, then composes
them into a const `WorldFrame -> CameraFrame` transform. The shared intermediate frame is a type
parameter, so trying to compose transforms whose frames do not meet is a compile-time error. Only
the timestamp is added at runtime, when the static transform is turned into a message.
